# Ikon AI App Development Guidelines

**Detailed API references are in docs/guides/. See the guide index at the bottom of this document.**

## Architecture

Ikon AI App is a cloud-native platform for building interactive, AI-powered multi-user experiences.

**App structure:** C# app runs in the cloud, streams reactive UI to browser clients via WebSocket. The app persists even when all clients disconnect. Multiple clients connect to the same app instance for real-time collaboration, games, and shared experiences.

**AI services (no setup required — the platform handles all API keys and connections):**
- `Emerge.Run<T>()` — LLM text generation and structured JSON output (Claude, GPT, Gemini, Grok, and more)
- `new ImageGenerator(model)` — AI image generation (Gemini, DALL-E, Flux, etc.)
- `new SpeechGenerator(model)` — text-to-speech (ElevenLabs, Azure, OpenAI, Google)
- `new SpeechRecognizer(model)` — speech-to-text (Whisper)
- `new VideoGenerator(model)`, `new EmbeddingGenerator(model)`, `new WebSearcher(model)` — other AI services

**UI system:** Declared in C# inside `UI.Root(content: view => { ... })`. The `view` parameter type is `UIView` (a class). There is NO `IView` interface or alias and NO `ViewContext` type — declaring a helper as `static void Render(IView view, ...)` or `(ViewContext view, ...)` fails with `CS0246: type 'IView'/'ViewContext' could not be found`. Always type the view parameter as `UIView`: `static void RenderStep(UIView view, ...)`. `UIView` provides component methods: `view.Text()`, `view.Button()`, `view.ScrollArea()`, `view.TextField()`, etc. Nested content lambdas receive their own `UIView view` parameter.

**State:** `Reactive<T>` (shared across all clients), `ClientReactive<T>` (per-client), `UserReactive<T>` (per-user). Changes automatically trigger UI updates — only the diff is streamed to clients.

**Styling:** Crosswind — Tailwind-like utility classes in C# string arrays, with a motion animation system for declarative keyframe animations (`motion-[...]`).

**Audio:** `private Audio Audio { get; } = new(app);` — audio synthesis (Ikon.Resonance), effects, playback, and client microphone/camera capture.

**Namespaces:** All Ikon namespaces are auto-imported via `GlobalUsings.cs` — no manual `using` statements needed for Ikon types.

## Development Focus

- Most development happens in the C# app, including styling
- LLM text generation uses `Emerge.Run<T>()`. Other AI services (image, speech, video) are standalone classes instantiated directly
- UI is declared inside `UI.Root([Page.Default], content: view => { ... })` — components are methods on the `view` lambda parameter
- Crosswind styling: Tailwind-like syntax in style arrays, with motion animation system
- `Reactive<T>` for shared state, `ClientReactive<T>` for per-client state — changes trigger UI updates automatically
- All Ikon namespaces are auto-imported via `GlobalUsings.cs`
- Only modify frontend-node when integrating custom React UI components
- Developers can freely add any NuGet packages to C# app or npm packages to frontend

## Common Pitfalls

These are the recurring hallucination + footgun classes seen across generated Ikon apps. Each one compiles or runs cleanly in the wrong shape and silently breaks the app — read this list before writing UI code.

- **Reactive UI re-render is implicit. There is NO `view.Dynamic`, `view.Watch`, `view.Bind`, `view.Observe`, `view.When`, `view.Live`, `view.Reactive`, or any other wrapper component for reactive rendering.** When you read `_x.Value` inside a UI lambda (e.g. `view.Text([…], _name.Value)` or `if (_open.Value) { view.Box(…); }`), the framework records that dependency and automatically re-renders the enclosing subtree on change. Just read `.Value` directly. Inventing `view.Dynamic(reactive, content: view => …)` causes CS1061 ("UIView does not contain a definition for Dynamic").
- **`Emerge` is a static class, not an injected service.** Call `Emerge.AskAsync(prompt)` or `Emerge.Run<T>(model, ctx, pass => …)` directly. There is no `IEmerge`, no `app.Services.GetRequiredService<IEmerge>()`, no constructor-injection pattern. The same goes for `Audio`, `UI`, and other helper handles — `Audio` is `new(app)` in the app class, not service-resolved.
- **Not every view component takes `props:`.** `view.Text`, `view.Button`, `view.Box`, `view.Image` and most input/display components accept `props:` for HTML attributes. `view.Column`, `view.Row`, `view.Grid` and pure layout primitives do NOT — `style:` / `styleId:` / `key:` / `content:` only. Passing `props:` to a layout primitive produces CS1739.
- **`LLMModel` has NO `Default` value.** Canonical enum values include `Claude46Sonnet`, `Claude45Sonnet`, `Claude45Haiku`, `Gemini25Flash`, `Gemini25Pro`, `Gpt5Mini`, `Gpt5`, `Grok420Reasoning`. Pick a specific model per `Emerge.Run<T>(LLMModel.X, …)` call. `LLMModel.Default` produces CS0117 — default to `Claude46Sonnet` for general chat / reasoning, `Claude45Haiku` for fast cheap text.
- **AI-service results are NULLABLE — null-guard them before use, or the build fails with CS8602** ("dereference of a possibly null reference"; the build runs warnings-as-errors). An AI call can fail/return nothing, so the result type is nullable: `Emerge.Run<T>(…).FinalAsync()` returns `(T? result, KernelContext context)`; the static `ImageGenerator.GenerateAsync(prompt)` returns `ImageGeneratorResult?`; likewise `VideoGenerator`, `SpeechGenerator`, etc. produce nullable/optional results. Guard once, right after the call, then use the non-null value: `var (recipe, ctx) = await Emerge.Run<Recipe>(…).FinalAsync(); if (recipe is null) { _error.Value = "Generation failed"; return; }` and `var img = await ImageGenerator.GenerateAsync(prompt); if (img is null) { return; } view.Image([…], data: img.Data, mimeType: img.MimeType);`. Use `?.`/`??` when reading into the UI from reactive state (`card.Recipe?.Title ?? "Untitled"`). Do NOT dereference the raw result (`recipe.Title`, `img.Data`) without a guard. (The streaming form's `Completed<T>.Result` inside `if (ev is Completed<T> c)` is the value for that case — handle the non-`Completed` events too.)
- **`Emerge.Run<T>` takes THREE args — `(LLMModel model, KernelContext context, Action<EmergePass<T>> configure)` — and returns an `IAsyncEnumerable<EmergeEvent<T>>`, NOT the result. The prompt is NOT a positional arg; it goes in the configure lambda as `pass.Command`.** Two shapes go wrong, both seen repeatedly: (a) passing a bare prompt string — `Emerge.Run<T>(LLMModel.X, prompt)` — is **CS1501** "no overload for method 'Run' takes 2 arguments"; (b) deconstructing the stream without `.FinalAsync()` — `var (result, _) = await Emerge.Run<T>(…)` — is **CS8130** ("cannot infer the type of implicitly-typed deconstruction variable") + **CS8183** ("implicitly-typed discard"). Copy this canonical one-shot call whole — every piece (the three args, `pass.Command`, `.FinalAsync()`, the null guard) is load-bearing: `var (result, ctx) = await Emerge.Run<MyResult>(LLMModel.Claude46Sonnet, new KernelContext(), pass => { pass.Command = userPrompt; }).FinalAsync(); if (result is null) { _error.Value = "Generation failed"; return; }`. The streaming form keeps the same three args but iterates instead of `.FinalAsync()`: `await foreach (var ev in Emerge.Run<T>(LLMModel.X, new KernelContext(), pass => { pass.Command = userPrompt; })) { … }`.
- **`onSubmit:` and `onClick:` lambdas that contain `await` must be `async`.** Writing `onSubmit: text => { return; }` inside a `Func<string, Task>` produces CS0126 and CS1643. Use `onSubmit: async text => { await SendAsync(); }`.
- **`autoScrollKey:` on `view.ScrollArea` is `string?`, not a Reactive or list.** Pass a string that changes when content changes: `autoScrollKey: _messages.Value.Count.ToString()`. Passing a `Reactive<List<…>>` produces CS1503.
- **`view.TextField` has TWO overloads — never mix positional + named args.** Overload A starts `(view, Reactive<string> bind, style, …)`; Overload B starts `(view, style, value, …)`. Writing `view.TextField(["flex-1"], bind: _input, …)` makes C# pick overload A (because `bind:` exists only there), and the positional `["flex-1"]` falls into the `Reactive<string>` slot → CS1744. Use ALL named arguments: `view.TextField(bind: _input, style: ["flex-1"], onSubmit: async t => …)`. Same caution applies to any component with multiple positional-first overloads — when in doubt, name everything.
- **TextField `disabled:` must NOT be bound to fast-changing reactive state.** Binding `disabled: _busy.Value` or `disabled: _phase.Value != null` re-mounts the input on every flip and drops keyboard focus mid-typing — the textbox becomes unusable. Static `disabled: true` for read-only fields is fine. To gate a submit during async work: leave the TextField enabled, gate the action on the Button (`disabled: _busy.Value`) and early-return in the submit handler.
- **`onClick:` is `Func<Task>?` — ALWAYS write it `async`.** Every clickable component's `onClick:` (including `view.Box`, `view.Button`, `view.Image`) takes a `Func<Task>`, so the lambda must return a `Task`. The non-async forms all FAIL: `onClick: () => _foo.Value = x` binds as an expression lambda returning the assigned value (CS0029/runtime); `onClick: () => { _foo.Value = x; }` is a void-body statement lambda that can't convert to `Func<Task>` (**CS1643** "not all code paths return a value"). The ONLY correct shape is `onClick: async () => { _foo.Value = x; }` — keep it `async` even when the body has no `await`. (`view.Box` DOES accept `onClick:` for a clickable container — it's `Func<Task>?` like the rest.)
- **Only `view.Box`, `view.Button`, `view.Image`, and `view.Link` take `onClick:`. `view.Text` and the layout primitives (`view.Row`, `view.Column`, `view.Grid`) do NOT** — passing `onClick:` to them is **CS1739** ("no parameter named onClick"). The HTML/React prior "any element can be clickable" does not hold here. To make a piece of text clickable (e.g. a sortable column header), wrap it: `view.Box([…], onClick: async () => { … }, content: v => v.Text([…], "Label"))`, or use `view.Button([…], onClick: async () => { … }, content: v => v.Text([…], "Label"))` when it should read as a button (see the `sortable-list-header` pattern).
- **`view.Button`: pass `onClick:` (and `style`) by NAME — never a positional click handler.** Two correct shapes: style-first `view.Button(["px-4 py-2"], label: "Save", onClick: async () => { … })`, or text-first `view.Button("Save", onClick: async () => { … }, style: ["px-4 py-2"])`. The footgun is a POSITIONAL second argument: `view.Button("Save", async () => { … })` puts the lambda into the `style[]` slot (the 2nd positional parameter of the text-first overload is `style`, not `onClick`) → CS1744 / CS1503. The label may be the first positional string, but the handler is ALWAYS `onClick:` named.
- **Copy / share / download are declarative `view.ActionButton` actions — NOT imperative `ClientFunctions` calls.** To copy text to the clipboard: `view.ActionButton([…], action: ActionKind.CopyToClipboard, options: new CopyToClipboardActionOptions { Text = theText }, content: v => v.Icon([Icon.Sm], name: "clipboard-copy"))`. There is NO `ClientFunctions.CopyToClipboardAsync`, no `ClientFunctions.RunJavaScriptAsync`, and no clipboard method on `ClientFunctions` at all — inventing one is **CS0117** ("ClientFunctions does not contain a definition for CopyToClipboardAsync"). The "call a clipboard API on the client" prior is wrong; these run client-side with no server round-trip. Same shape for `ActionKind.Share` (`ShareActionOptions { Title, Text }`), `ActionKind.DownloadFile`, and `ActionKind.ShowNotification` (`ShowNotificationActionOptions { Title, Body }`). **`DownloadFileActionOptions` takes `Data` (a `byte[]`, NOT a string) and `Filename` (lowercase `n` — NOT `FileName`, NOT `Name`):** `new DownloadFileActionOptions { Filename = "notes.md", Data = System.Text.Encoding.UTF8.GetBytes(text) }` — any other property name is **CS0117**. (See the `copy-and-share-action-row` pattern.)
- **`ScrollArea`: bare `style:` styles the outer wrapper (same as `rootStyle:`); `viewportStyle:` styles the scrollable content area.** Both work as positional or named — `view.ScrollArea(["flex-1 min-h-0"], viewportStyle: ["px-4"], content: …)` is the common shape. If padding seems wrong, you probably meant `viewportStyle:` instead of `style:`.
- **`AudioContainer` carries PCM samples, not encoded bytes.** Properties are `float[] Samples`, `int SampleRate`, `int ChannelCount` — there is no `.Data` / `.MimeType`. To play `SpeechGenerator` output: declare `private Audio Audio { get; } = new(app);` then `Audio.SendSpeech(audio)` per chunk in the `await foreach`. `ClientFunctions.PlaySoundAsync(byte[], string)` is a different API for already-encoded MP3/WAV blobs.
- **Audio is synthesized SERVER-side and streamed to clients — there is NO browser Web Audio API, no client-side JavaScript synthesis, and no custom React component needed to make sound.** To play tones, drum hits, beeps, or any synthesized sound: build the PCM `float[] samples` server-side (hand-fill a `float[]` with a sine/decay envelope, or use `Ikon.Resonance.Synth` oscillators/filters/envelopes) and stream them with `private Audio Audio { get; } = new(app);` then `await Audio.SendAsync(samples, sampleRate, channelCount, isFirst: true, isLast: true, streamId: id)`. Do NOT reach for `ClientFunctions` to inject/run JavaScript, a `view.CustomComponent` wrapping the Web Audio API, or an `AudioContext` in the frontend — those are the web-dev reflex and are not how Ikon plays sound. (`ClientFunctions.PlaySoundAsync(byte[], mimeType)` exists only for an already-encoded MP3/WAV blob, not for synthesis.) See the audio-video guide for the synthesis + `Audio.SendAsync` pattern.
- **`WebSearcher` uses `SearchPagesAsync(SearchConfig)`, not a positional `SearchAsync(string, int)`.** Real shape: `await searcher.SearchPagesAsync(new SearchConfig { Query = q, MaxResults = 5 });`. `SearchResult` exposes `Url`, `Title`, `Content`, `Mimetype`, `Keywords` — there is no `Snippet`; use `result.Content` for the body text.
- **`view.Image`'s first positional arg is the style array (like every other component) — `src` / `data` are NAMED.** The shapes are `view.Image(["w-72 h-72 rounded"], src: url, alt: "…")` for a URL and `view.Image(["w-72 h-72"], data: bytes, mimeType: "image/png", alt: "…")` for raw bytes. Do NOT write `view.Image(url, ["w-72"], …)` — that puts the URL in the `string[] style` slot (CS1503) and the style array in the `string? src` slot (CS1739/CS0029). There is no `classes:` parameter. Style FIRST, source NAMED.
- **A custom frontend node — `view.AddNode(type: "x.y", …)` — renders BLANK unless a React resolver for `"x.y"` is registered in `frontend-node/src/app.tsx`. This is the most dangerous trap in the framework because NOTHING in the build catches it:** the C# compiles and the Critic scores it 9/10 (both only see C#); only at runtime does the browser log `[UIRenderer] No renderer for node type x.y` with a blank area where your component should be. A working custom component needs ALL FOUR parts together — a React component, a resolver, `registerModule(...)` in `app.tsx`, and the C# `AddNode` extension. **So do NOT reach for `view.AddNode` / custom node types by default.** Build everything you can from native `view.*` components first. For a chart / diagram / visual that native components don't cover, render it SERVER-SIDE to SVG or PNG and display it with `view.Image([…], data: bytes, mimeType: "image/svg+xml")` — zero frontend code, can't go blank. **Strongly avoid hand-building a custom React component in this flow — it reliably spirals** (the C# `AddNode` plumbing and the React resolver + `registerModule` registration must all line up, and a partial attempt — an orphan resolver file that isn't registered, or a registered module without the C# extension — STILL renders blank). Even for a "genuinely interactive" surface like a freehand sketchpad or whiteboard, do NOT reach for `view.AddNode`: instead implement the closest experience from native `view.*` components, or render a server-side SVG/PNG snapshot via `view.Image(...)`, accepting reduced live-interactivity. A correct, fully-rendered simpler app beats a blank "perfect" one. (If a custom component is truly unavoidable, `guide("custom UI component — React resolver + registerModule in app.tsx + AddNode C# extension")` first and write ALL four parts — but expect the build's frontend-renderer gate to reject any custom node type whose resolver isn't registered.) Never emit a custom node type and assume it renders.
- **EXCEPTION — real-time MULTI-USER (collaborative editing, multiplayer games with local rendering) is the ONE case where a custom React canvas + a custom Teleport `.tp` message is the RIGHT tool, not native components.** When the brief needs many clients to see each other's high-frequency actions live — a shared whiteboard where everyone sees strokes appear, a multiplayer game with moving players, live cursors — native `view.*` and server-side SVG snapshots cannot express it (they have no client→client live channel). The deliberate, validated pattern: (a) declare a `Schema/<Name>.tp` message type (add `unreliable = true` for drop-tolerant high-frequency streams like positions/strokes); (b) build the four-part custom canvas component that sends/receives it via the SDK `appMessaging` helper (`appMessaging(client).send(Type, value)` / `.on(Type, handler)`); (c) on the server, `app.OnMessage<T>((payload, senderId) => …)` to receive and `app.SendMessageAsync(payload, targetIds)` to fan out — the **app is the router** (decide recipients explicitly; the server never auto-broadcasts app-local messages). Keep everything that ISN'T the live shared surface — toolbars, scoreboards, side panels — in native `view.*` reactive components; ONLY the high-frequency shared surface goes custom. Reference apps: **Ikon.App.CoWhiteboard** (collaborative whiteboard) and **Ikon.App.Arena** (multiplayer game). `guide("real-time multi-user custom .tp app — Schema/*.tp + appMessaging + custom canvas + server router")` for the complete end-to-end pattern before writing it.
- **Real-time-multiuser footguns (both seen in generated apps — and the codegen build gate now compiles the frontend too, so a broken import FAILS the build instead of silently shipping):** (1) **Import paths** — `appMessaging` comes from `@ikonai/sdk`; custom-UI renderer types (`UiComponentRendererProps`, `useUiNode`, `IkonUiComponentResolver`, `IkonUiModuleLoader`, `IkonUiRegistry`) from `@ikonai/sdk-react-ui`; the generated codecs (`toProtocolMessageX`, `fromProtocolMessageX`, `X_OPCODE`) from `'../generated/protocol/<name>'`. There is **NO `@ikonai/sdk-react`** package — importing from it fails the frontend build. (2) **Use the TYPED server API, not the untyped passthrough** — receive with `app.OnMessage<Stroke>(async (payload, senderId) => …)` and fan out with `app.SendMessageAsync(payload, targetIds)` to the recipients YOU choose (e.g. `app.Clients.Ids.Where(id => id != senderId && id != app.ClientContext.SessionId).ToList()`). Do **NOT** write `app.OnMessageReceived(async msg => await app.SendMessageAsync(msg))` — that untyped passthrough blindly re-broadcasts the raw message with no typing, no chosen recipients, and no late-join, which is not the server-as-router model.
- **For SINGLE-USER freehand drawing / sketch / image-annotation apps, use the NATIVE `view.ImageEditorCanvas` — do NOT hand-build a custom canvas component.** (For a MULTI-user live-shared drawing surface, that's the real-time-multiuser exception above — `ImageEditorCanvas` is a single-user annotator and has no client→client sync.) It's a built-in drawing surface with its renderer already registered, so it just works. Validated shape: `view.ImageEditorCanvas(style: ["w-full h-full min-h-[500px]"], src: optionalImageUrl, brushColor: _color.Value, brushWidth: _size.Value, tool: _tool.Value /* "brush" | "eraser" | "text" */, onSave: async args => { /* args holds the edited image */ }, onHistoryChange: async args => { _canUndo.Value = args.CanUndo; _canRedo.Value = args.CanRedo; })`. Undo / redo / save are fired by **bumping integer counter props** — `triggerUndo:` / `triggerRedo:` / `triggerSave:` each take an `int?`; increment a `Reactive<int>` and pass `.Value` to trigger the action (there is no `Undo()` method to call).
- **File upload: the simplest correct flow is accept-then-complete; the callbacks' `AssetUri` is a `string?`, NOT the `AssetUri` struct.** `view.FileUpload(accept: ["image/*"], onUploadComplete: async args => { … })` — the simplest accept is to **OMIT `onUploadStart` entirely** (auto-accept), then read the finished upload in `onUploadComplete` where `args.AssetUri` (a URI **string**) and `args.LocalTempFilePath` are available. If you DO supply `onUploadStart`, its return type is `Task<FileUploadStartResult>` (NOT `Task<bool>`): write `onUploadStart: async args => true` (a `bool` implicitly converts to `FileUploadStartResult` and `async` lifts it into the `Task`) — do NOT write `onUploadStart: args => Task.FromResult(true)`, which infers `Task<bool>` and fails with **CS0029**. To pre-route the bytes into the asset system, `onUploadStart: async args => new FileUploadStartResult(assetUriString)`. Store the result in `Reactive<string?>` (the URI string) — NOT `Reactive<AssetUri?>`; the `AssetUri` struct is a different type used by the `Asset` API (`new AssetUri(str)`), and assigning the callback's `string?` to it is CS0029. When you later read the asset back, every `Asset.Instance.*` op (`GetMetadataAsync`, `GetBytesAsync`, `SetBytesAsync`, …) takes the **`AssetUri` struct**, so wrap the stored URI string and null-guard first: `if (uri is null) return; var bytes = await Asset.Instance.GetBytesAsync(new AssetUri(uri));` — passing the raw `string?` is **CS1503**. To unwrap a genuine `AssetUri?` (nullable struct) use `.Value` after a null check, never the `!` operator (which only suppresses reference-type warnings).
- **Field initializers cannot reference instance members — no other fields, no `this`, no the primary-constructor `app` parameter.** Writing `private readonly Action _wire = () => { app.OnClientJoined(...); _hostId.Value = …; };` or any field initializer that touches another instance field / `app` produces **CS0236** "a field initializer cannot reference the non-static field, method, or property". Reactive fields init with a literal default only (`new(0)`, `new([])`). Put anything that touches instance state — event wiring (`app.OnClientJoined(...)`), reads of other fields — inside `Main()` or a method, never a field initializer.
- **Database access: open a connection PER-OPERATION via a helper method — do NOT hold one as a field.** `AppDatabaseConnection` is a STATIC class, so a field of it (`private AppDatabaseConnection _db;`) is **CS0723** "cannot declare a variable of static type", and a connection field initialized from `app` (`private readonly DbConnection _conn = AppDatabaseConnection.Create(app, "db");`) is **CS0236** (field initializer can't reference `app`, see above). The ASP.NET/EF "inject a long-lived DbContext field" prior does NOT apply here. `AppDatabaseConnection.Create(app, "name")` returns a fresh ADO.NET `DbConnection` you open and dispose per use. Canonical pattern: `private DbConnection OpenConn() => AppDatabaseConnection.Create(app, "contactsdb");` then in each method `await using var conn = OpenConn(); await using var cmd = conn.CreateCommand(); cmd.CommandText = "..."; …`. Ensure the table exists once in an `app.OnStarting(...)` handler (a `CREATE TABLE IF NOT EXISTS`). Prefer raw `DbConnection` + SQL; EF Core / `DbContext` is opt-in and only worth it when you explicitly need migrations. Any `AppDatabaseConnection.Create(app, "X")` also requires `"X:postgres"` under `Databases` in `ikon-config.development.toml`.
- **Tailwind/Crosswind fraction widths only exist for common denominators — there is NO `w-3/10`, `w-7/10`, etc.** Valid fractions are halves, thirds, quarters, fifths, sixths, and twelfths (`w-1/2`, `w-2/3`, `w-3/4`, `w-2/5`, `w-5/6`, `w-7/12`, …); a tenth like `w-3/10` silently produces no CSS so the element gets no width. For a fixed arbitrary percentage use an arbitrary value (`w-[30%]`). For a **runtime-computed** percentage (e.g. a data-driven bar/progress width) you CANNOT use `w-[{pct}%]` — Crosswind only generates classes it can see in source at build time, so a string-interpolated class never exists. Set it inline instead: `view.Box(["h-2 bg-sky-500"], props: new Dictionary<string, object> { ["style"] = $"width: {pct}%" })`.
- **NEVER add `using Ikon.*;` directives — every Ikon namespace is already imported via `GlobalUsings.cs`.** Just write the type name (`WebSearcher`, `Emerge`, `Audio`, …). Inventing an import for a feature you're about to use — `using Ikon.Agent.WebSearch;`, `using Ikon.Agent;`, `using Ikon.WebSearching;` — produces **CS0234** "namespace does not exist in the namespace 'Ikon'" because those namespaces are made up. The real namespaces (e.g. `Ikon.AI.WebSearching`) are ALL already in the global usings; you never need a per-file `using` for an Ikon type. **This rule applies ONLY to Ikon namespaces.** A third-party NuGet package you add (e.g. `QRCoder`, `Markdig`) is NOT in GlobalUsings — it still needs its own `using QRCoder;` / `using Markdig;`, or its types fail with CS0246/CS0103.
- **`MessageAuthor` value comparison uses the static instances, not the nested types.** `Author == MessageAuthor.User` works (User is a static `MessageAuthor` instance). `Author == MessageAuthor.UserAuthor` does NOT compile — `UserAuthor` is a nested record type, not a value. For type-pattern matching use `is`: `Author is MessageAuthor.UserAuthor`. Same for `System` / `SystemAuthor`, `Agent(name)` / `AgentAuthor`, `Thread(id)` / `ThreadAuthor`.
- **`Reactive<List<T>>` collection mutation must go through the extensions, not `.Value.Add(...)`.** `_items.Add(x)` mutates and notifies in one call. `_items.Value.Add(x)` mutates the underlying list without firing the change event — UI doesn't refresh. Same for `Remove`, `Clear`, `RemoveAt`, `Insert`, `RemoveAll`.
- **`Reactive<T>` / `ClientReactive<T>` / `PersistentReactive<T>` / `PersistentUserReactive<T>` / `PersistentSessionReactive<T>` are `private readonly` FIELDS initialized with `new(defaultValue)` — ONE positional arg.** They derive their storage key from the field name via `[CallerFilePath]` / `[CallerMemberName]` — pass NOTHING else. RIGHT: `private readonly ClientReactive<int> _count = new(0);`, `private readonly PersistentUserReactive<List<TodoItem>> _todos = new([]);`. WRONG (all produce CS1503 / CS7036 build errors): `new ClientReactive<int>(app, 0)` — IApp is NOT a ctor arg; `app.ClientReactive<int>(0)` / `view.ClientReactive(0)` — there is NO such method on IApp or UIView; `new PersistentUserReactive<T>("key", default)` — there is no key arg. The ASP.NET / EF Core mental models (`context.Get<T>("key")` or `new(context, "key", default)`) do not apply to Ikon reactives. **For the default value, give an explicitly-typed value or a collection expression — never a bare target-typed `new()`.** `new([])` for an empty list is fine, but `new PersistentReactive<Dictionary<int, Player>>(new())` is **CS0121 ambiguous**: the inner `new()` matches both the `(T value)` ctor and an internal `(UseDefault)` ctor overload. Write the value explicitly: `new(new Dictionary<int, Player>())`, `new([])` (list/array), `new("")`, `new(0)`.
- **`UIView` is a component-rendering surface only — it has NO methods for creating or subscribing to reactive state.** `view.ClientReactive(...)`, `view.Reactive(reactive, lambda)`, `view.Persistent(...)`, `view.Watch(...)`, `view.Bind(...)` ALL fail with CS1061. Reactive state is declared at class level (see field-init pitfall above), and subscription is implicit — reading `.Value` inside a UI lambda registers the dependency. There is no view-side "reactive scope" API.
- **Per-client state is implicit — `ClientReactive<T>.Value` auto-resolves to the CURRENT client. Do NOT fetch a client id and look the value up manually.** There is no `view.ClientContext`, no `view.ClientSessionId`, and no `_x.Get(clientId)` / `_x.For(clientId)` accessor on `ClientReactive<T>` — all produce CS1061. Inside any UI lambda or `onClick`/`onSubmit`/`onValueChange` handler, just read and write `_x.Value`; the framework scopes it to the client that's rendering or that fired the event. The web-session mental model ("get the session id, then index per-session state") does NOT apply — a handler that needs per-client behavior takes no `clientId` parameter. (If you genuinely need the joining client's identity in a lifecycle handler, that's `app.OnClientJoined(async ctx => …)` with `ctx.ClientSessionId` — but that is the `Context`, not anything on `view`.) **Client/session ids are `int`, never `string`:** `ReactiveScope.ClientId` is `int`, `ctx.ClientSessionId` is `int`, `ReactiveScope.ClientIdOrNull` is `int?`, and `app.Clients[id]` is indexed by `int`. Type any client-id local, method parameter, or reactive as `int` / `int?` (e.g. `Reactive<int?> _hostId`, `void StartTimer(int clientId)`) — a `string clientId` param or `Reactive<string>` host-id state produces CS1503/CS0266 the moment you assign `ReactiveScope.ClientId` to it.
- **`Main()` MUST return after `UI.Root(...)`. Do NOT add `await Task.Delay(Timeout.Infinite)` or any other infinite wait at the end of Main().** `UI.Root` registers the reactive renderer and returns immediately; the Ikon server framework keeps the process alive on its own. If Main() blocks forever, `OnServerStartedAsync()` never completes and the server dies with `TimeoutException` after 2 minutes (visible only in logs — the build is clean and the Critic gives the file a 9, but the app never actually starts). The complete Main() body is just `UI.Root([Page.Default], content: view => { … });` followed by closing braces.
- **ASCII quotes ONLY in C# source — never Unicode curly quotes `“` `”` `‘` `’`.** Even inside a `$"..."` interpolated string literal, the C# compiler does not accept smart quotes — CS1002 "expected ;" appears at the curly-quote position because the lexer sees a stray Unicode character, not a string delimiter. Some code editors auto-correct typed `"` into `“` and `”`; do not let that happen in your output. The same rule applies to apostrophes (`'` is C#, `’` is not).
- **A literal double-quote inside an interpolated `$"..."` string MUST be escaped `\"` — an unescaped inner `"` closes the string early and desyncs the parser for the whole rest of the file.** Wanting the text `Add card to "Done"` and writing `$"Add card to "{col}""` ends the string at the first inner quote, leaving `{col}` as loose tokens → a **CS1002 / CS1010 / CS1026** cascade: dozens of phantom "; expected" / ") expected" errors across the file, all from this ONE real mistake. When a single file suddenly shows a burst of those codes, look for an unescaped `"` (or an unbalanced `(`/`{`) — don't try to fix each reported line. Fix by escaping the quotes — `$"Add card to \"{col}\""` — or, simplest, dropping them — `$"Add card to {col}"`. For text with many literal quotes, switch to a raw interpolated string `$"""Add card to "{col}"."""`, where `"` needs no escaping.
- **Raw-string interpolation: match `$` count to brace nesting.** `$"""..."""` (single `$`) treats single `{` as interpolation and `{{` as a literal `{`. `$$"""..."""` (double `$$`) flips it: single `{` is literal and `{{...}}` is interpolation. Writing `$"""...{{animal}}..."""` (single `$` with double-brace interpolation) produces CS9007/CS9008 "raw string literal does not start with enough $ characters". **Default to the simplest form**: if your template has interpolations AND literal `{` / `}` chars (e.g. JSON examples in an LLM prompt), use `$$"""..."""` with `{{x}}` interpolations and single `{` / `}` for the literals. If the template has interpolations but NO literal braces, use plain `$"""..."""` with `{x}`. If the template is just static text, use bare `"""..."""` with no `$`. Never reach for `\n` escape soup in single-line `"..."` strings — raw strings already preserve newlines.
- **TextField's `bind:` is a non-nullable `Reactive<string>`. Don't pass `bind: null` — and don't dodge that with `bind: null!`.** When you don't have a Reactive to bind to, OMIT the `bind:` argument entirely; the value flows through `value:` + `onValueChange:` instead. Passing `bind: null` produces CS8625 ("Cannot convert null literal to non-nullable reference type"); silencing it with the null-forgiving `bind: null!` compiles but is still wrong — `bind` and `value:` are two different modes, so a nulled bind alongside `value:` breaks the input. Pick ONE mode. The full no-bind pattern: `view.TextField(value: _input.Value, onValueChange: async v => { _input.Value = v; }, onSubmit: async _ => …, clearOnSubmit: true)`.
- **`bind:` exists ONLY on `view.TextField` / `view.TextArea`. `view.Select`, `view.Checkbox`, `view.Switch`, `view.Slider`, `view.RadioGroup` do NOT have `bind:`** — passing it is **CS1739**. The state parameter AND the callback both differ by component. `view.Select` / `view.RadioGroup` take a **`string` `value:`** + `onValueChange:`; `view.Slider` takes a **`IReadOnlyList<double>` `value:`** + `onValueChange:`; but `view.Checkbox` / `view.Switch` take a **`bool` `isChecked:`** + `onCheckedChange:` — on those two `value:` is a `string?` form value, NOT the checked state, so passing the bool to `value:` is **CS1503** (`cannot convert 'bool' to 'string?'`). E.g. `view.Select(value: _stage.Value, options: [..], onValueChange: async v => { _stage.Value = v; })`, `view.Checkbox(isChecked: _done.Value, onCheckedChange: async c => { _done.Value = c; })`, and `view.Switch(isChecked: _enabled.Value, onCheckedChange: async e => { _enabled.Value = e; })`. Don't carry the TextField `bind:` prior over to the other inputs. Also for `view.Select`: `options:` is `IReadOnlyList<SelectOption>` where each option carries BOTH value and label — `options: [new SelectOption("won", "Won"), new SelectOption("lost", "Lost")]`. There is NO parallel `labels:` parameter (CS1739) and `options:` is not a `string[]` (CS1503) — don't bring the HTML `<select>` "options + labels arrays" model; one `SelectOption(value, label)` per choice. And `view.Slider` is range/multi-thumb, so its `value:` and `onValueChange` are **list-valued `IReadOnlyList<double>`**, not a scalar: `view.Slider([Slider.Default], value: [(double)_bpm.Value], min: 0, max: 200, onValueChange: async v => { _bpm.Value = (int)v[0]; })`. Scalar `value: _bpm.Value` is CS1503 and `(int)v` is CS0030 — wrap the value in `[...]` and read `v[0]`.
- **Overlay `onOpenChange` callbacks hand you a `bool?`, not a `bool`.** `view.Dialog` / `AlertDialog` / `Popover` / `Toast` / `Collapsible` (and `Select`'s `onOpenChange`) are `Func<bool?, Task>` — the parameter can be null. Branching on it directly is **CS0266** ("cannot convert `bool?` to `bool`"): `onOpenChange: async open => { if (!open) … }` and `open ? a : b` both fail. Coalesce or compare to a literal: `onOpenChange: async open => { _open.Value = open ?? false; }`, or `if (open == false) …` / `if (open == true) …`. (`Reactive<T>.Value` itself is NOT nullable — this is specifically the `onOpenChange` parameter; don't start `?? `-guarding `.Value` reads to chase this error.)
- **`view.Dialog`, `view.AlertDialog`, `view.Link`, `view.Button` accept the natural param shapes — don't hunt for an exact name.** Both overlays take `title:` / `description:` (string convenience) AND a `content:` lambda (full custom body) — use whichever fits: `view.Dialog(open: _open.Value, onOpenChange: async o => _open.Value = o ?? false, title: "Delete entry?", description: "This cannot be undone.", content: v => { /* extra body + buttons */ })`, or `view.AlertDialog(open: _open.Value, onOpenChange: async o => _open.Value = o ?? false, title: "Delete file?", description: "This cannot be undone.", cancelLabel: "Cancel", actionLabel: "Delete", onAction: async () => { await DeleteAsync(); })`. Link and Button both take `text:` OR `label:` for the label string — `view.Link(text: "Open", href: url)` / `view.Link(label: "Open", href: url)` both work, as does a `content:` lambda for rich content. `view.TextField` and `view.TextArea` take a `label:` for a field label rendered above the input — `view.TextField(bind: _name, label: "Name", placeholder: "Jane")` — no need to hand-roll a separate Text + input. (No component takes a React-style `header:` prop; for a fully custom overlay body build it inside `content:` with `Dialog.Header`/`Dialog.Title`/`Dialog.Description` children.)
- **Flat size constants (`.Xs` / `.Sm` / `.Md` / `.Lg`) exist on `Icon` ONLY — `Button.Sm` and `Text.Xs` / `Text.Sm` are CS0117 ("does not contain a definition for 'Sm'").** `view.Icon([Icon.Sm], …)` works, and the LLM over-generalizes that to every style class. It doesn't hold: a BUTTON bakes size into the combined variant constant — `Button.PrimarySm` / `Button.OutlineMd` / `Button.GhostLg` (or the nested `Button.Size.Sm` to compose) — never a bare `Button.Sm`. TEXT uses SEMANTIC constants, not sizes — `Text.Body` / `Text.BodySm` / `Text.Small` / `Text.Caption` / `Text.Label` / `Text.H1`…`Text.H6` — or just a Tailwind size class in the array (`view.Text(["text-xs text-muted-foreground"], …)`); there is no `Text.Xs` / `Text.Sm`.
- **`view.Button` has NO `variant:` / `color:` / `size:` parameter — the variant AND size are ONE baked style constant in the style array.** The React/shadcn prior `view.Button(variant: "destructive", size: "sm", label: "Delete")` is **CS1739** ("does not have a parameter named 'variant'"). Put the look in the array instead: `view.Button([Button.ErrorMd], label: "Delete", onClick: async () => { … })`. The variant constants are `Button.Primary*` / `Button.Secondary*` / `Button.Outline*` / `Button.Ghost*` / `Button.Error*` / `Button.OutlineError*` (each with a `Sm` / `Md` / `Lg` size suffix, e.g. `Button.PrimaryMd`). **For a destructive / delete button use `Button.ErrorMd` (filled) or `Button.OutlineErrorMd` (outlined) — there is NO `Button.Destructive` / `Button.Danger` constant** (CS0117 "does not contain a definition for 'Destructive'").
- **There is NO `view.Spinner()`-style loading component you need to hand-roll — `view.Spinner()` is built in.** It renders an animated circular loading indicator: `view.Spinner()` (or `view.Spinner(size: SpinnerSize.Lg)`, or `view.Spinner(["text-sky-400"])` to recolour). Use it directly for async/pending states — `if (_loading.Value) { view.Spinner(); }`. (The equivalent hand-rolled form is a `view.Box` with the `Default.Icon.Spinner` style; prefer the typed component.)
- **A conditional style list — `view.X(cond ? [..] : [..], …)` — does NOT compile (CS1503).** A ternary of two collection expressions has no common type (collection expressions are target-typed), so the compiler can't infer `string[]` for the `style` parameter and misbinds the `cond` bool as a positional argument. This bites the most common conditional-styling shapes: dark-mode wrappers, drag-over highlights, active/selected rows. Two fixes: (a) extract a typed local first — `string[] style = isActive ? ["bg-active", "text-primary"] : ["text-muted"]; view.Box(style, content: …);` — or (b) keep ONE array and make the *element* conditional: `view.Box(["rounded p-2", isActive ? "bg-active" : "bg-card"], content: …)`. Form (b) is usually cleaner for toggling a few classes.
- **`IApp` is a generic interface — ALWAYS pass type arguments, and declare the two records `public`.** The canonical app class shape is `[App] public class MyApp(IApp<SessionIdentity, ClientParameters> app)` with `public record SessionIdentity(string UserId)` and `public record ClientParameters(string Name = "Anonymous")` (use empty `()` if you have no fields). Two failure modes: (1) writing the primary-constructor param as bare `IApp app` (no type args) produces CS0305 "requires 2 type arguments"; (2) declaring the records WITHOUT `public` (`record SessionIdentity(...)`) makes them `internal` by default — but the app class is `public`, so the constructor's `IApp<…>` type argument becomes less accessible than the constructor → **CS0051 "Inconsistent accessibility"**. BOTH records must be `public record`. The scaffold's existing app file already has the canonical `public record` shape — preserve it; don't rewrite the records or the constructor signature from scratch (rewriting from memory is exactly how the `public` modifier gets dropped).
- **Lifecycle events: use the `app.OnStarting(...)` / `app.OnClientJoined(...)` extension helpers.** The raw events (`app.StartingAsync`, `app.ClientJoinedAsync`, etc) take an `AsyncEventHandler<TEventArgs>` delegate — a single-arg `Func<TEventArgs, Task>`. The .NET / standard event-handler prior `(sender, args) => ...` does NOT match (CS1593), and zero-arg lambdas `() => ...` ALSO don't match. The friendly extensions take the LLM-natural shape directly: `app.OnStarting(async () => await InitDbAsync())`, `app.OnStopping(async () => await CleanupAsync())`, `app.OnClientJoined(async ctx => ...)` (receives `Context` directly — `ctx.SessionId`, `ctx.UserId`, also `ctx.ClientSessionId` as a same-thing alias), `app.OnClientJoined(async (ctx, parameters) => ...)` (typed-parameters overload — receives the joining client's `TClientParameters` directly, e.g. `parameters.Name`, no `app.Clients[...]!.Parameters` drill needed), `app.OnClientLeft(async ctx => ...)` / `app.OnClientLeft(async (ctx, parameters) => ...)`, `app.OnMessageReceived(async msg => ...)`. The event-args wrapper types (`StartingEventArgs`, `ClientJoinedEventArgs`, etc) exist but the extensions skip them. Don't invent `AppStartingEventArgs` / `AppStoppingEventArgs` — those types don't exist; the canonical names omit the `App` prefix.
